Data Engineering

Employee Sports Benefits Data Platform

Data engineering · ETL · Workflow orchestration

Fictional client scenario set by the programme.

Problem: A fictional company wanted to test the feasibility of two employee benefits and to estimate their financial impact.

Approach: An end-to-end pipeline that loads and validates HR and activity data, orchestrates the workflow, posts activities to Slack and presents indicators on a dashboard.

Technical implementation: Airflow DAGs orchestrate the workflow, with a PostgreSQL store, Superset dashboards and numbered Bash scripts as a manual fallback, all containerised with Docker Compose. The data are simulated employee and activity data (161 employees).

Validation: Data-quality checks run in the pipeline, and commute distances are validated with the Google Maps Distance Matrix API.

Outcome: A proof of concept; activity data is simulated, not read from a live service.

Healthcare Data Migration Pipeline

Data engineering · ETL · Database migration

Fictional client scenario set by the programme.

Problem: A fictional healthcare provider with scalability problems needed its medical records migrated from a CSV file to MongoDB.

Approach: A seven-step ETL workflow with automated cleaning and integrity testing, a containerised deployment, and a written study of cloud deployment options on AWS.

Technical implementation: Name standardisation and duplicate removal, and memory use reduced by 21% through categorical and datetime types. Built with Python, pandas, PyMongo, MongoDB, Docker, pytest and Poetry.

Validation: Five integrity tests pass under pytest. 54,966 medical records remain after cleaning (55,500 in the source file).

Outcome: A Docker Compose deployment of MongoDB with a web interface for the database, and an AWS comparison of DocumentDB, Atlas, EC2 and ECS.

Machine Learning and Retrieval

RAG Chatbot for Cultural Event Recommendations

Machine learning · Information retrieval · RAG

Fictional client scenario set by the programme.

Problem: Recommending cultural events in Paris so that answers are grounded in real listings rather than in the general knowledge of a language model.

Approach: A retrieval-augmented generation proof of concept using live Open Agenda data. Events are fetched from the Open Agenda API, cleaned and filtered to the past 12 months in the Paris region, with one text chunk per event, embedded and indexed for similarity search.

Technical implementation: A single LangChain chain serves both the Streamlit chatbot and the evaluation, with Mistral AI and FAISS. Built with Python, LangChain, Mistral AI, FAISS, Streamlit, RAGAS, pytest and Poetry.

Validation: Evaluation with RAGAS on 30 questions, and 25 automated pytest tests.

Outcome: A proof of concept: single-turn, one data source, manual rebuilds.

Data Analysis

EduGlobe Insights: Education Data Analysis

Data analysis · Statistical analysis · Visualisation

Fictional client scenario set by the programme.

Problem: Judging whether World Bank EdStats data can support the international expansion of an online education service for high school and university learners.

Approach: Exploration, cleaning and analysis of the five EdStats tables (indicator values, series catalogue, country metadata, country-series links, footnotes), downloaded separately from the World Bank and not included in the repository.

Technical implementation: Three Jupyter notebooks, using pandas, Matplotlib, Seaborn, Plotly and SciPy.

Validation: The indicators are assessed for relevance, completeness and reliability.
