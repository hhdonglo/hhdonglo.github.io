Data work alongside the research

Uncertainty quantification, scientific computing and machine learning for nuclear data are part of the research (see Research). This page collects complementary work in data engineering and data science, where the same habits apply: reproducible pipelines, tests that check the data, stated assumptions and results that can be reproduced.

Certification

The project-based programme covers the full data lifecycle: relational and NoSQL databases, ETL pipelines, containerisation, cloud services, workflow orchestration, streaming and retrieval-augmented generation. Selected projects

Each project was completed for a fictional client scenario set by the programme. Descriptions follow the repository documentation.

RAG Chatbot for Cultural Event Recommendations

Data engineering · Machine learning · RAG · Proof of concept

A retrieval-augmented generation proof of concept that recommends cultural events in Paris from live Open Agenda data, so answers are grounded in real listings rather than the general knowledge of a language model.

Data: events fetched from the Open Agenda API, cleaned and filtered to the past 12 months in the Paris region

Method: one text chunk per event, embedded and indexed for similarity search; a single LangChain chain serves both the Streamlit chatbot and the RAGAS evaluation (30 questions); 25 automated pytest tests

Scope: a proof of concept: single-turn, one data source, manual rebuilds

  • Python
  • LangChain
  • Mistral AI
  • FAISS
  • Streamlit
  • RAGAS
  • pytest
  • Poetry

Employee Sports Benefits Data Platform

Data engineering · Pipelines

An end-to-end pipeline for a fictional company, built to test the feasibility of two employee benefits and to estimate their financial impact: loading and validating HR and activity data, orchestrating the workflow, posting activities to Slack and presenting indicators on a dashboard.

Data: simulated employee and activity data (161 employees); commute distances validated with the Google Maps Distance Matrix API

Method: Airflow DAGs, a PostgreSQL store, data-quality checks, Superset dashboards and numbered Bash scripts as a manual fallback, all containerised with Docker Compose

Scope: a proof of concept; activity data is simulated, not read from a live service

Healthcare Data Migration Pipeline

Data engineering · Databases

A CSV to MongoDB migration for a fictional healthcare provider with scalability problems, with automated cleaning, integrity testing and a containerised deployment, plus a written study of cloud deployment options on AWS.

Data: 54,966 medical records after cleaning (55,500 in the source file)

Method: seven-step ETL workflow; name standardisation and duplicate removal; memory use reduced by 21% through categorical and datetime types; five integrity tests passing under pytest

Outcome: Docker Compose deployment of MongoDB with a web interface for the database, and an AWS comparison of DocumentDB, Atlas, EC2 and ECS

  • pandas
  • MongoDB
  • PyMongo
  • Docker
  • pytest

EduGlobe Insights: Education Data Analysis

Data analysis

An exploratory analysis of World Bank EdStats to judge whether the data can support the international expansion of an online education service for high school and university learners.

Data: the five EdStats tables (indicator values, series catalogue, country metadata, country-series links, footnotes), downloaded separately from the World Bank and not included in the repository

Method: exploration, cleaning and analysis in three Jupyter notebooks, with the questions of relevance, completeness and reliability of the indicators
